## 版本约定

- 建立可供迭代比较的基线时使用 `0.1.0`；在 `0.y.z` 阶段，增加可体验能力或内容规模时递增 `y`，局部修正或内容修订时递增 `z`。
- 每个版本都要有对应的 Git 提交和 `demo-vX.Y.Z` 标签；在本文件及同目录 `CHANGELOG.md` 更新版本和变化摘要。
- 内容变化须同时记录新的内容 SHA-256；只改界面或交互时内容哈希应保持不变。哈希用于确认内容是否变化，不代表质量或授权结论。
- GitHub Release 仅用于标记私有内部试验快照。内容体验、真机交互与权利审查未完成前，不得据此称为验收版或公开发布版。
- 未入 Git 的设计草稿不属于该版本。发布时只包含提交中跟踪的文件。
