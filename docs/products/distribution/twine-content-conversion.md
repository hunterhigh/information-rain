# Twine → 分发内容包转换契约

状态：内容制作规范 v2｜适用范围：当前读者网页的静态内容包｜更新：2026-10-09

“转换契约”比“通讯协议”更准确：这里约定的是**源故事如何变成内容包**，没有两个服务之间的通信。本文件描述现有产品可接受的输出，以及转换前的编辑与校验；不表示资料区的外部作品已获选制作或自动发布。当前格式和注册器以[内容池说明](../../../products/distribution/reader-web/content-pool/README.md)与[`register-distribution-content.mjs`](../../../scripts/register-distribution-content.mjs)为准。

## 1. 输入、产物与边界

| 阶段 | 输入或产物 | 规则 |
| --- | --- | --- |
| 源文件 | 同一作品的 `.twee`、`.tw`，以及需要时的 `.tws` | 记录文件路径、版本和 SHA-256；多个文件合并成一部作品解析，保留原文件，不直接在原件上清洗。`.tws` 若不能可靠解析，先导出文本。 |
| 转换工作表 | 节点对照、章节分段、状态处理和编辑决定 | 工作文件，供复核使用；不被读者网页加载。建议命名 `conversion-map.json`，结构见下文。 |
| 正式内容包 | `packs/<id>/world-entry.js` 和 `packs/<id>/images/<cover>.jpg` 或 `.png` | `world-entry.js` 内容必须是**纯 JSON 对象**，即使扩展名为 `.js`；封面位于同一包的 `images/` 内。 |
| 注册 | 内容包通过注册器检查后进入内容池 | 注册会改动内容池和展示顺序，属于单独的内容上架步骤；研究资料不自动注册。 |

转换范围是**一个经编辑确认的完整故事体验**，不要求把 Twine 里的菜单、成就、设置、战斗系统和每个 passage 原样搬进读者端。若删掉某项会破坏因果，则必须改写成可读节点或停止转换，不能静默丢失。

[研究资料区](../../research/content-supply/README.md)里的《凌霄錄》只保存故事文件，用于阅读与结构参考；其系统依赖已清出活动资料区。要验证运行时路径或实际转换，须先从记录的来源提交取得依赖并核对原故事。不能把资料子集当成可运行的 Twine 工程。

## 2. 源文件解析

1. 按 `:: passage-name [tags]` 切分文本 passage，记录原始文件、原始名称、标签和正文。Twine 特殊段落如 `StoryTitle`、`StoryData`、`StoryInit`、脚本、样式、菜单和 widget 单独分类，不直接算故事节点。
2. 识别静态选择：`[[target]]`、`[[label->target]]`、`[[label|target]]` 等，以及经实际故事格式确认的宏或链接，例如 SugarCube 的 `<<link>>...<<goto>>`。链接文案与目标分开记录；正文里的装饰性链接不自动算故事选择。
3. 解析前确定故事格式和真实起点。不能仅凭第一个文件、第一个 passage、文件名顺序或方括号链接数猜起点。
4. 对 `<<if>>`、`<<set>>`、`(if:)`、变量、随机数、背包、战斗、动态目标、嵌入段落及外部资源做依赖清单。**不能通过删掉宏或 HTML 标签来宣称转换完成。** 无法确定实际文案、选项或目的地时标为“待人工处理”。
5. 建立源图，检查重复 passage 名、缺失目标、隐藏条件、无出口段落、回环和可到达的结局。人工沿主要选择路径读完各章和至少一条结局，记录未核验路径。

## 3. 作品到内容图的映射

| Twine 语义 | 当前内容包映射 | 必须作出的判断 |
| --- | --- | --- |
| 故事起点 | 顶层 `startNode` 指向 `data` 中的节点 ID | 去除标题页/菜单后，选真实叙事起点。 |
| 故事 passage | `data.<nodeId>.text` | 将格式标记转成可直接阅读的正文；合并过短的过渡节点，拆分过长或混合多个抉择的节点，保留事件因果。 |
| 静态选项 | `exits.<direction> = targetId` 与同方向的 `labels.<direction>` | 每个普通节点有 1–2 个出口，只用 `left/right`；同一节点的两个选项不能指向同一后果。`up/down` 保留给作品切换。文案须描述行动或代价，不能只有“继续”。 |
| 条件选项、变量后果 | 经编辑重写后的静态分支，必要时复制少量情境节点 | 同一节点对所有进入路径必须语义成立。若分支依赖未保留状态而无法表达，停止本次静态转换并提出产品格式变更。 |
| 章节/卷次（如有） | 转换工作表的 `chapters`，正文可自然表达章节转场 | 单篇故事不必人为拆章。当前运行内容包**没有章节字段或章节导航**；如需读者端真正按章显示，另做产品设计。 |
| 结局 passage | `data.<endId>` 中 `isEnding: true`、`text`、`title`、`summary` | 结局回应主线与选择后果；回放、返回菜单、下一周目链接不作为结局出口。 |
| `StoryTitle`、作者、标签、封面、时长 | 顶层展示字段 | 标题可参考来源，作者署名、简介、阅读时长、标签、主题与封面由内容编辑确认；不能由 passage 计数推定阅读时长。 |

所有进入同一节点的路径都要能接上同一段正文。如果此前选择改变角色、持有物、关系或关键事实，须改写成互不冲突的描述，或保留分别对应的节点。合并节点前必须做这一检查。

## 4. 正式包字段与约束

顶层必填：`id`、`title`、`author`、`desc`、`duration`、`image`、`tags`、`theme`、`nodes`、`ends`、`startNode`、`data`。`id` 与目录名一致，只用小写字母、数字、`_`、`-`。`tags` 是非空字符串数组；`nodes` 和 `ends` 是实际的非结局/结局节点数。`image` 指向 `./images/` 下的 JPEG/PNG。`theme` 由编辑按现有主题样式选择，不从 Twine 的 CSS 盲目复制。

`data` 是以稳定节点 ID 为键的对象。每个节点有非空 `text`；普通节点有 1–2 个 `left/right` 出口，且每个出口都有相同方向的非空 `labels`。整部作品至少有 **10 个可达的非结局剧情节点**，不是要求每条路径经过 10 次选择。结局有 `isEnding: true`、非空 `title` 和 `summary`，没有出口。`startNode` 必须存在；所有正式节点和结局从起点可达。至少有一个结局。分三选时须改写为两次有实质变化的抉择，不能只用空转页凑节点。

字段局部示意（**不足 10 个节点，不能注册**）；实际包仍需真实封面和经过编辑的完整故事：

```json
{
  "id": "sample-story",
  "title": "示意故事",
  "author": "示意作者",
  "desc": "一句说明故事冲突的话。",
  "duration": "8分钟",
  "image": "./images/sample-story.jpg",
  "tags": ["抉择"],
  "theme": {"bg": "#101820", "accent": "#e3b66b", "particles": "rain"},
  "nodes": 1,
  "ends": 2,
  "startNode": "n1",
  "data": {
    "n1": {
      "text": "人物遇到一个必须回应的事件。",
      "exits": {"left": "e1", "right": "e2"},
      "labels": {"left": "留下来帮助同伴", "right": "独自带走线索"}
    },
    "e1": {
      "text": "同伴得到帮助，但线索消失了。",
      "isEnding": true,
      "title": "留下",
      "summary": "保住同伴，失去线索。"
    },
    "e2": {
      "text": "你带着线索离开，同伴必须独自面对后果。",
      "isEnding": true,
      "title": "离开",
      "summary": "得到线索，失去同伴的信任。"
    }
  }
}
```

示意只展示字段形状；正式转换仍应保留作品中真正有意义的多轨分支。节点 ID 不依赖源 passage 顺序，可用 `n1`、`n2`、`e1` 等；一旦进入编辑与复核，保持稳定。原 passage 到正式节点的多对一、一对多关系写在工作表中。

## 5. 转换工作表与验收

建议工作表结构如下；它是编辑记录，不是运行时接口：

```json
{
  "schemaVersion": 1,
  "sourceWorkId": "example",
  "sourceCommit": "<固定提交>",
  "outputId": "sample-story",
  "chapters": [],
  "mapping": [
    {"sourcePassage": "Start", "sourceFile": "story.twee", "outputNodes": ["n1"], "treatment": "edited"}
  ],
  "stateDecisions": [
    {"sourceExpression": "$inventory.hasKey", "treatment": "rewrite", "reason": "静态节点无法保存背包状态"}
  ],
  "unverifiedPaths": []
}
```

验收顺序：

1. **结构**：源文件齐全；起点、主线冲突、结局及存在时的章节已标注；每条保留选择有出处或明确的编辑改写说明。
2. **语义**：逐条检查选择后的事实连续性；条件与变量没有被无声丢弃；每个保留结局回应它所承诺的情节；不得用同一段泛化结局掩盖不同后果。
3. **格式**：正文无未处理的 Twine 宏、HTML 控件或模板变量；节点出口不超过四个；无悬空目标、不可达节点或普通死端；计数与图一致。
4. **阅读**：至少走通各章主线路径及每类保留结局；记录路径、选项、耗时和发现的问题。文学质量与有效阅读时长由人评估，不能由注册器代替。
5. **产品校验**：成包后运行 `node scripts/register-distribution-content.mjs <内容包目录>` 注册；再运行 `node scripts/register-distribution-content.mjs --check` 核对内容池。注册前先完成内容审定与封面制作。

无法满足第 2 项时，输出“需重写”或“当前格式不支持”的明确结论，不生成貌似可用的包。对资料区的外部作品，本契约当前只用于分析结构和创作新的独立作品；真正制作时须确定具体内容范围与编辑责任。
