# 资料库选题 → 独立世界故事：执行计划

## 任务与完成位置

本工作从[资料库的 38 个候选方向](../../../research/content-supply/notes/2026-10-08-fission-expanded-audit.md)中逐个选择，把某个方向发展为**能单独阅读、有实质分支和剧情闭环的原创世界故事**。这一步交付的是故事本身，不是上线内容包。候选数量只是工作入口，不是生产指标；不为了消耗清单而做薄弱作品。

**本阶段完成状态称「故事就绪」**：独立设定、人物、规则、完整节点正文与选项均已写出；每条保留路径可读且有收束；结构和编辑审查均完成。它不需要封面。38 篇现已注册到公开实验预览；2026-10-09 起按[决定 0016](../../../project/decisions/0016-binary-story-vertical-worlds.md)改为双选项、整部至少 10 个剧情节点，原有 23 部也纳入修订。公开预览状态不自动等于独立审稿完成。

“世界故事”是本产线的工作单元：一个读者可以从头进入并获得完整体验的故事。产品本体中“世界”和“作品”的最终关系仍[待确认](../ontology.md)；这里不借工作术语替产品定名。

| --- | --- |

| 本执行计划与故事工作目录 | `docs/products/distribution/story-production/`；这是分发产品的内容制作工作，不写入外部研究结论。 |

| 产品静态图与字段规则 | [Twine 转换契约](../twine-content-conversion.md)和[当前内容池格式](../../../../products/distribution/reader-web/content-pool/README.md)。 |
| 读者端已上线内容 | `products/distribution/reader-web/content-pool/packs/`；只接收后续有实际封面的正式包。 |

每个进入制作的工作单元最少有 `BRIEF.md`、`STORY.md`、`REVIEW.md`。`BRIEF.md` 记录来源候选 ID 与源节点、准备保留的体验效果、将要改变的题材/人物/规则、故事独立性、核心问题与按[叙事编辑标准](EDITORIAL-STANDARD.md)选定的文风卡。`STORY.md` 是本阶段**唯一可编辑的故事正文与节点图**：每个节点有稳定 ID、完整正文和指向目标 ID 的选项；结局也有 ID 与正文。`REVIEW.md` 留下逐路径检查、文笔与沉浸审读、改写决定、未解决问题、实际试读时间与当前状态。不要复制资料库原文作为草稿正文。

本阶段先用易读的 Markdown 写作和审稿。故事就绪后才将 `STORY.md` 映射到正式 JSON；若后续数量证明手工转录易出错，再为固定 Markdown 结构编写无第三方依赖的转换与图检查脚本。转换后的 JSON 不能与继续编辑的 Markdown 并列成为两份权威：转换期间先冻结 Markdown，若发现故事问题，回到 Markdown 修订后重新生成/映射，并在 `REVIEW.md` 记录版本。封面和注册不阻碍故事稿的完成。

为便于后来接续，每个工作单元采用同一最低记录方式：`BRIEF.md` 写“读者处境、核心问题、关键选择与代价、预期结局、来源节点与改写边界”；`STORY.md` 按 `## n01 · 场景名` / `## e01 · 结局名` 排列节点，完整正文后用 `- → n02：选项文案` 指向下一节点，结局不列出口；`REVIEW.md` 用表格记录“路径 ID 序列、该路兑现的后果、实读用时、问题及修订”，并在页首写当前状态和下一动作。方向槽位可在正式包映射时分配，故事稿中的选项顺序不预设滑动方向语义。格式服务于阅读和核对，首个试作若暴露明显不便，应修订本约定而不是让所有故事背负它。

## 单个故事的实际工作顺序

### 1. 选一个候选，核实它真正能支撑什么

从候选清单按**读者钩子、选择张力、与现有内容池的差异、所需原创量**选择；不按原作节点数或结局数排序。核对候选在源文件中的起点、关键选择、后果和终局。第二轮 `structure.json` 仅是静态图，不把有条件路径当作已试玩；首轮则直接阅读 `.tw/.twee`。在 `BRIEF.md` 区分“源作确有”“推断”“本故事将新写”。若源段只有气氛，没有足以支撑选择的因果，回到候选清单换题。

### 2. 先确定故事体验，再定世界设定

在 `BRIEF.md` 用一段话答清：读者是谁，眼前必须处理什么，为什么现在不能拖，做错/放弃会失去什么。列出要保留的**效果或设计机制**，例如“眼前的资源赠与在末尾形成互救”，不要保留原作的角色姓名、专有设定、标志性道具组合或句子。新题材要改变因果环境和人物关系，而不是只替换词语。选择的新世界必须让关键抉择自然成立，也能独立理解，不依赖读者知道资料库原作。同时确定叙述视角、声音、节奏和意象的文风卡；明确继承的是源作技法，还是另选适合新世界的文笔。

### 3. 先写结果矩阵，再写路径图

先确定每一种结局回答同一个核心问题的方式：人物得到什么、付出什么、谁承担后果、哪些伏笔在这里兑现。再从结局倒推关键选择，形成一页节点与选项关系图。原则是至少有两个读者能理解其代价的实质选择；选择须改变事件、关系、可知信息或结局。可合流，但合流节点必须承认不同路径的事实。原作的状态、背包、分数或循环若在当前静态图中无法表达，改写为读者可见的分支与后果；无法保住核心体验就停在设计阶段并记录格式缺口，不造一个貌似可用的简化版。

路径设计以当前阅读器的图约束为界：整部作品至少有 10 个可达的非结局剧情节点，每个普通节点最多两个出口；第一个选项映射 `left`，第二个映射 `right`，上下手势只切换作品。起点和结局明确。节点下限不能靠无后果转场凑数；当核心选择承诺不同结果时，应给出不同结果，而非换一句总结。结局后重玩不算故事出口。

### 4. 完成所有正文，然后脱离界面审读

在 `STORY.md` 写出开端、过程、转折、各条路线与所有结局的完整正文。先读一条代表路径是否像一篇值得读完的故事，再读其他路径；去掉只为凑节点的转场、重复说明和机械问答。开篇尽快建立处境，节点持续带来行动、发现或后果；选项说清行动或可感代价，结局兑现人物命运，不用抽象说教替代事件。每段都应推进事件、判断、关系或情绪，或提供必要停顿；不把“钩子”误写成每段末尾的廉价悬念。按选定文风写出具体的文学质感，并在改稿时清理解释主题、回避冲突、过度缓冲等模型常见的防御性写法。具体检查见[叙事编辑标准](EDITORIAL-STANDARD.md)。每篇作品可以有自己的篇幅、语言与结构；不为了达到时长强迫等待或填充文字。

### 5. 分三层复核并修订

1. **文学与独立性**：不看资料库能否看懂、愿不愿继续、人物是否有动机、反转是否有前置信息；文风卡能否兑现、场景是否沉浸、逐段是否有牵引、是否出现防御性写作；与来源的区别是否深入到设定、因果、人物和表达，而非仅改名。记录仍显得过近或过于通用的构造并重写。
2. **选择与因果**：逐条走完主要路径和每类结局；检查选项承诺是否兑现，前置状态、时间、地点、身份、物件和关系在汇合后是否矛盾；相同结局是否抹去了此前重大选择。
3. **图与产品适配**：节点 ID 唯一、目标存在、全部保留节点可达、普通节点无意外死端、结局无外出、整部不少于 10 个剧情节点、每节点 1–2 个选择；无 Twine 宏或依赖浏览器隐藏状态的正文。结构检查通过不代替前两项。

把每条实读路线、用时和改动写入 `REVIEW.md`。阅读时长只由实际走读报告，不由节点数、文案估算或 Twine 延时宏推断。若将来开展项目规则所说的正式内容体验试验，再另按三种结构、每种至少十分钟有效阅读和所有者试玩的要求办理；单篇故事审稿不是那项试验。

### 6. 判定故事就绪，留清晰停点

完成前五步、没有未写的分支或待补终局，文风、沉浸、文学与逐段牵引按[叙事编辑标准](EDITORIAL-STANDARD.md)审读并修订，且 `BRIEF.md`、`STORY.md`、`REVIEW.md` 相互一致，才能在[工作索引](README.md)标为「故事就绪」。不能因为自动图检查通过或写完主线就升级。若尚需重写，状态保持「在写」并记录下一项具体编辑动作；若题目不成立，记为「搁置」和理由，不强行产出。

## 后续在本线程如何继续

- 每次接续先读本计划、[叙事编辑标准](EDITORIAL-STANDARD.md)、[工作索引](README.md)中的当前状态，以及正在制作故事的 `BRIEF.md`、`STORY.md`、`REVIEW.md`；只按需要回查来源。不从旧聊天猜剧情进度，也不每次重扫 38 条。
- 一次只推进一个故事到可观察的编辑停点。每轮结束更新 `REVIEW.md`：已完成什么、还缺哪条路径、下一动作、需要重审的判断；同步索引状态。
- 首个试作建议 **S02**（有限清醒资源与未知生物的交换）：核心反馈链短，最适合验证从资料选题到独立故事、再到静态图的完整做法。试作后修订模板与检查方法，再继续 L04、P01、W01、V02 等不同结构；这个顺序是工作建议，可随故事质量证据调整。
- 每做完几篇再比较：题材与情绪是否重复、每篇是否真的有不同的读者问题、哪种来源结构需要太多补写。无必要时不建批量生成器；当人工转录、路径检查或状态追踪反复出错时，再实现最小自动化。
