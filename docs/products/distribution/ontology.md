# 分发产品业务语言本体

状态：**草案，待产品讨论校正**｜适用对象：当前分发产品及其后续实现

本体是产品概念和关系的共同词典。它帮助产品讨论、界面文案、内容格式和后端数据使用相同含义。这里的条目先依据当前 Demo、已确认决定和现有内容包整理；状态为“待确认”的概念不能直接当作最终产品规格或数据库设计。

技术愿景术语另见[技术愿景本体](../../vision/ontology.md)。例如，“信息雨”描述信息组织方法；本产品在界面和用户沟通中的正式产品名尚未决定。

## 产品边界

当前主动维护的是**分发产品**：读者发现内容，进入一部作品，在作品提供的后继中继续体验，并能返回与保存自己的阅读线索。当前实现是静态 Demo，内容预写、服务端和账号尚未接入；本体描述的是要持续打磨的产品对象，不表示这些能力已经上线。

## 业务术语表

| 首选术语 | 暂定业务定义 | 当前 Demo / 内容包中的对应 | 状态 |
| --- | --- | --- | --- |
| **分发产品** | 面向读者发现、进入和继续体验内容的产品。 | 当前 Demo 的产品方向；与创作工具产品分开。 | 已确认方向；产品名未定 |
| **读者** | 使用分发产品浏览、阅读、选择和保存个人线索的人。 | 当前使用者；尚无服务端身份。 | 暂定 |
| **作品** | 一项可被发现和进入的完整内容体验，拥有自身标题、作者/署名、简介、封面及可继续的内容结构。 | 页面展示为作品/世界；内容包顶层对象当前称 `world-entry`。 | 核心对象；“作品”与“世界”关系待确认 |
| **世界** | 当前内容数据和界面使用的概念，可能指承载一部作品的情境，也可能是作品本身。 | 内部字段、注册包和部分 UI 使用 `world`。 | 语义待确认；不应自动与“作品”画等号 |
| **节点** | 读者在作品中某一位置看到的一段内容及其可继续方式；结局是无法继续选择的终止位置。 | `nodes`、`ends`；节点含正文和方向到目标的映射。 | 当前实现概念；产品用语待确认 |
| **后继选项** | 从当前节点进入某个可到达后继的选择，以及对应的选择文案。 | 内容包中的方向键和选项文本。方向是交互位置，不预设固定剧情语义。 | 定义依据决定 0003；展示名称待确认 |
| **阅读路径** | 读者从作品入口经过节点和选项形成的个人体验顺序。 | Demo 的方向选择与本地足迹可以部分体现；具体恢复与分叉规则尚未作为服务承诺确定。 | 产品概念；保存规则待定 |
| **阅读进度/会话** | 为了继续体验而记录的读者当前位置及必要上下文。 | 当前 Demo 没有服务端进度恢复。 | 目标能力候选；字段和保留周期待定 |
| **发现入口** | 帮助读者找到作品的浏览入口，可包括主页、发现页、搜索和主题筛选。 | 当前有主页、发现、搜索等 UI；最终入口关系和默认页待定。 | 当前 UI 有实现；产品信息架构待验证 |
| **收藏** | 读者主动标记、以后可再次找到的作品或内容位置。 | 有收藏页与收藏交互。 | 当前实现；跨设备保存待定 |
| **足迹** | 帮助读者回看此前进入或体验过的作品/位置的记录。 | 当前记录页保存本地线索。 | 当前实现；它与阅读进度、阅读路径的区别待确认 |
| **内容包** | 用于交付、审核和导入作品数据及相关素材的文件集合。 | `world-entry.js`、创作简报和 9:16 封面。 | 当前内部工作术语 |
| **内容注册** | 将内容包校验并加入 Demo 内容池的维护操作，不是读者注册账号。 | PowerShell 注册器、`registry.json` 和生成注册文件。 | 当前工具概念；面向用户文案不得简写成“注册” |

## 关系草图

```text
读者 ──浏览──> 发现入口 ──呈现──> 作品
读者 ──进入──> 作品 ──包含──> 节点 / 结局
节点 ──提供──> 后继选项 ──到达──> 下一节点或结局
读者的选择 ──形成──> 阅读路径
读者 ──保存──> 收藏、足迹；将来可能保存阅读进度/会话
内容包 ──经内容注册──> 当前内容池（内部维护流程）
```

## 需要产品讨论后定稿的核心区别

1. **作品与世界**：用户打开的是“作品”，还是进入一个“世界”；一个世界是否能含多部作品？当前代码命名不能替产品作答。
2. **节点与内容单元**：节点是否作为用户可见概念，还是只作为编辑/系统内部结构？用户界面继续使用什么自然语言？
3. **路径、足迹、进度与会话**：分别解决回看、继续、撤销还是跨设备恢复？在关系确认前不将它们合并成一个笼统“记录”。
4. **主页、发现与搜索**：它们是并列页面、入口和工具关系，还是主页包含发现内容？当前 UI 不能直接视为最终信息架构。
5. **署名、作者和创作者**：内容显示的作者身份与将来可能登录的创作者账号是否为同一实体？当前没有账号系统，暂不假设。

## 更新约定

讨论新功能、数据表或 API 时，先检查是否已有本体术语。若需新增或改变含义，先更新本文件并记录决定，再修改多个页面或数据格式。字段名可以为实现方便而保留旧称，但必须在映射中说明，不能让内部变量反过来定义用户语言。
