# 文档、归档与版本协同规则

状态：当前工作规则｜适用范围：Information Rain 单仓库

## 信息放在哪里

| 内容 | 唯一权威位置 | 边界 |
| --- | --- | --- |
| 项目入口与当前导航 | `START-HERE.md` | 指路并呈现当前状态，不复制愿景或规格全文。 |
| 长期技术愿景 | `docs/vision/technical-vision.md`、`docs/vision/ontology.md` | 技术愿景有自己的本体，不直接规定某个产品的功能。 |
| 产品业务定义与计划 | `docs/products/<product>/` | 每个产品独立拥有本体、简报、决定和路线图；一个产品的内容不能自动成为另一个产品的规格。 |
| 产品源码与运行资源 | `products/<product>/` | 每个产品源码、构建、部署和发布边界独立。 |
| 商业策划 | `docs/business/` | 市场进入、创作者交换、收入和运营等业务判断；候选策略不是已批准功能。 |
| 外部研究 | `docs/research/<topic>/` | 保存来源、日期、范围和证据限制；按市场、架构、合规等主题分类。 |
| 项目治理与协作 | `docs/project/` | 跨产品共用的基线、决定、会议、路线图、阶段门与流程。 |
| 实验和旧样本 | `experiments/` | 放暂时性验证和历史样本，不再存放当前产品源码。 |

## 产品目录约定

- 当前分发产品代码在 `products/distribution/`；其业务本体与路线图在 `docs/products/distribution/`。
- 工具 Agent 的代码位子预留在 `products/tool-agent/`，产品资料位子预留在 `docs/products/tool-agent/`。它尚未进入实施，不在预留目录里伪造产品规格。
- 同一个仓库不代表共享构建或部署。每个正式产品分别建立 Pages 项目或其他发布单元；只有确定的公共协议/组件才另行评估 `shared/`。
- 网页构建输出放根目录 `dist/`，必须可由产品源码重复生成，不手工维护第二份网站副本。

## 文档状态与协同

- **当前 / Active**：有效依据，后续工作遵循。
- **草案 / Draft**：可以讨论，不能视为决定或规格。
- **未决 / Open**：记录了等待处理的问题；完成后同步关闭状态、工作基线和索引。
- **已取代 / Superseded**：由明确的新决定取代，保留原因和新文档链接。
- **已归档 / Archived**：停止推进，仅用于追溯，不进入当前工作队列。

每份长期文档开头说明状态、适用产品或范围、日期；索引写标题、状态和用途，不复制正文。跨目录引用使用 Markdown 相对链接，移动文件时同一项变更中更新所有引用和目录索引。

## 新增资料的归档流程

1. 先读[工作基线](working-baseline.md)，判断属于哪个产品或项目共用事项。
2. 区分**外部证据**（`docs/research/`）、**商业判断**（`docs/business/`）、**产品规则**（`docs/products/<product>/`）和**技术愿景**（`docs/vision/`）。不要因研究某个产品就把研究结果直接写成产品决定。
3. 在所属目录现有 README 索引中增加一条链接。若无对应主题，先创建明确主题目录和索引，避免再建立一份平行入口。
4. 要改变已批准范围、关键术语或架构时，在 `docs/project/decisions/` 新增决定，并更新产品本体/路线图；会议记录只记讨论过程与决策指向。
5. 代码变更通过 Git 追踪；对用户可见的变化写产品 `CHANGELOG.md`。工作完成后更新[工作基线](working-baseline.md)。

## Git、版本与发布

- `main` 表示可恢复的主线。较大工作可使用短期分支，不为形式强制要求 PR。
- 产品版本按 SemVer 记录；项目级规则变更写根 `CHANGELOG.md`，产品可见变化写对应产品变更日志。
- 发布标记需要对应可恢复的 Git 提交；标签不等于用户验收或公开发布授权。
- 部署配置、源码目录、文档说明必须指出同一产品目录，避免一个项目路径含多个产品输出。

## 归档与迁移

历史实验默认留在 `experiments/`，索引说明停止原因、当前替代和证据价值。当前活动代码不应为保留实验编号而继续留在实验目录。

搬迁前先查明相对链接、构建路径和索引；搬迁时保留 Git 历史，并在同一变更中更新 README、构建脚本、项目基线和相关链接。搬迁后检查所有本地 Markdown 链接和必要的产品构建路径。
