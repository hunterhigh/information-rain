# 文档、归档与版本工作规则

状态：工作规则草案｜适用范围：当前 Information Rain 仓库

## 文档各自负责什么

| 文档类型 | 权威文件 | 用途 |
| --- | --- | --- |
| 项目入口 | `START-HERE.md` | 告诉协作者项目是什么、现在哪条线在做、按什么顺序阅读。 |
| 技术愿景 | `README.md` 与 `docs/vision/ontology.md` | 保存长期设想和愿景术语；不作为产品功能规格。 |
| 产品本体 | `docs/products/<product>/ontology.md` | 保存该产品的业务名词、定义、关系、实现映射和待确认问题。 |
| 产品简报 | 产品目录中的 `PRODUCT-BRIEF.md` 或现有 `DEMO-BRIEF.md` | 说明用户、价值、主要流程、范围和体验边界。 |
| 实施路线 | `docs/products/<product>/roadmap.md` | 记录阶段目标、交付、依赖、退出依据和状态。 |
| 当前基线 | `docs/project/working-baseline.md` | 记录当前产品、版本、分支/提交、活动阶段、未决事务和下一步。 |
| 决定 | `docs/project/decisions/NNNN-*.md` | 保存已采纳选择、依据、边界和后续影响。 |
| 会议 | `docs/project/meetings/YYYY-MM-DD-*.md` | 保存讨论带来的变化、未决问题和决定来源，并链接权威文档。 |
| 变更日志 | 根 `CHANGELOG.md`；当前分发 Demo 的 `experiments/round-01/distribution-demo/CHANGELOG.md` | 根日志记录项目级变化；产品日志记录当前分发产品的变化。未来若正式产品源码迁出实验目录，连同产品日志一起迁移并更新引用。 |
| 归档索引 | `experiments/archive/README.md` | 告知哪些样本已撤回/停止、为何保留、什么仍可参考。 |

每项信息只设一个权威来源；其他文档链接它，而不是复制整段内容。

## 状态标记

- **当前/Active**：目前有效，后续工作应遵循。
- **草案/Draft**：可以讨论，不能当成已决定规格。
- **未决/Open**：有明确问题等待选择，如 `UT-01`。
- **已取代/Superseded**：旧材料由明确的新决定取代，保留理由和新文件链接。
- **已归档/Archived**：停止推进的历史材料，仅供追溯，不进入当前实施队列。

文件开头应写状态、适用范围和最近更新时间；一旦变为已取代或归档，保留原件并加上指向当前权威材料的说明，不通过悄悄覆写历史来伪造连续性。

## 工作与决定如何入档

1. 开始实质工作前，从工作基线找到当前有效版本、产品本体、路线图阶段和相关决定。
2. 新工作必须说明它服务于路线图中的哪个目标。仍是设想的内容标成候选；项目所有者确认的方向才进入决定/本体/路线图。
3. 不可逆或会影响后续实现的选择写入编号决定；会议记录简要说明变化及原因并链接决定。
4. 代码变化由 Git 提交追踪；对用户或维护者有意义的变化写入产品变更日志。内部重排可省略，不能用 changelog 代替提交记录。
5. 每次可恢复发布创建 Git tag，版本日志指向对应标签和提交。当前私有 Demo `demo-v0.1.0` 为既有历史标签，不重写。
6. 工作结束时更新工作基线：当前提交/版本、阶段、完成证据、未决事务、下一步和阻塞。

## Git 与版本记录

- `main` 表示可恢复的当前主线；保持提交历史，不为“看起来整齐”改写已共享记录。
- 较大的单项工作可使用短期分支；完成后经明确检查合回主线。当前以小范围协作为主，不为了形式强制建立 PR 流程。
- 版本按 SemVer 记录为 `MAJOR.MINOR.PATCH`：对外承诺/兼容接口变化、产品能力增加、向后兼容修复各自对应主/次/补丁级别。`0.x` 表示仍在产品形成阶段；具体发布是否公开需独立授权并过阶段门。
- 每个发布日志至少包含版本、日期、用户可见变化、重要内部变化、已知限制、未通过或未完成事项、标签/提交指针。未发布内容集中在 `Unreleased`。
- 变更日志说明“用户得到什么变化”，Git 提交说明“这次改了什么”；两者互补。

## 归档边界

- 归档内容不删除，也不出现在当前任务清单中；索引要标出停止原因、有效替代和仍可引用的证据。
- 历史测试、撤回 Demo 和比较候选默认留在原路径，通过索引标注，避免路径迁移造成断链。
- 当前唯一主动推进版本及未决事务不算归档。动画对比页继续关联 `UT-01`，不是已采纳设计。
- 如果材料确需搬迁，先确认引用清单并更新所有相对链接，再一次性移动和验证。
