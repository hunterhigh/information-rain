# 0014：分发作品统一内容池

日期：2026-09-30｜状态：已采纳并实施｜范围：分发产品静态 Demo

## 背景与决定

此前 19 部作品写在 `index.html`，另四部放在内容包中；页面把两处数据拼接，注册器仍指向历史实验目录。这个结构让编辑、排序、校验和未来接入内容服务出现两条路径。项目所有者要求统一作品格式和位置，并为后续扩展留出边界。

- 23 部作品统一以纯 JSON 对象存于 `products/distribution/reader-web/content-pool/packs/<id>/world-entry.js`，封面存于本包的 `images/`。`index.html` 不再保存作品正文。
- `display-order.json` 单独维护作品 ID 的展示顺序。注册新作品追加到末尾；已有作品顺序可独立调整并重新生成目录。
- `registry.json` 与 `registry.generated.js` 是从作品包和展示顺序生成的校验/运行产物。当前静态页面只读取生成目录；未来内容 API 可接替这一加载边界。
- 注册器改为活动产品目录，校验所有作品的字段、节点关系、封面、ID 和展示顺序。静态构建先检查目录一致性，发布包只包含运行数据及图片，不包含创作草稿。
- 封面来源比例不强制相同。原有 19 张 1344×768 横图保持字节不变，原有四张 1080×1920 竖图保持不变；界面仍使用 9:16 舞台和原有裁切。新作品建议交付 9:16 封面。

## 迁移核对

迁移后仍是 23 部作品、478 个节点、200 个结局、713 条选择。将运行时图片路径映射回旧路径后，全部作品数据的 SHA-256 与迁移前一致：`c2f0e069ecc22637ac9fda555be588a59c997cf8d83d0e243d2839a741bebfcd`。19 张迁移封面逐张核对为字节相同。旧页面中的作品顺序被保存到 `display-order.json`。

## 边界

这仍是 Git 管理的静态内容源；调顺序或改作品需要重新生成并部署。没有引入数据库、后台管理、个人推荐、账号或服务端阅读记录。对外展示权利和内容审查遵循现有决定。先前[决定 0009](0009-distribution-content-registry.md)中的“双来源”和强制 9:16 输入约束由本决定更新；其四个交付包的来源与历史校验记录仍保留。
