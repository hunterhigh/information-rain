# 决定 0003：让内容决定可达路径

状态：已确认｜日期：2026-09-24

## 背景

Round1 的首版“兴趣地形”推演把三个后继、固定预览、会话内保留未选方向、回退后可改选等设为整个平台的规则。这把某一种体验写成了信息雨的边界，限制不同内容形成不同路径与后果。

## 项目所有者的纠正

> 我的原则永远是尽量给予自由度，而不是过度设计。返回旧的位置后进入当时没选的方向应该由该内容决定。而不是你。你的目标应该是设计一个产品允许这种多样性发生

## 当前决定

产品提供多走向内容的承载能力；具体信息位置由其内容机制决定可达后继、预览方式、返回后的行为、未选方向是否仍可进入，以及状态如何变化。相同产品可以容纳可反复探索、只能回看、一次性消逝、回到旧位置后产生新方向等不同内容。系统负责让这些规则对用户可理解、可执行，并记录已实际发生的路径。

“尽量给予自由度”是设计偏好，不是要求所有内容无条件允许撤销或永久保留所有分叉。自由度还包括内容可以建立有后果的限制。平台层只保留实现多样性所需的通用能力与必要的交互一致性，不把某个内容的规则扩张为全局法则。

## 对 round1 的影响

- “兴趣地形”的三个边缘预览、会话内冻结邻接和可回退改选降为一种待验证的内容配置，不再代表项目原则或 product-01 的既定机制。
- 候选研究要检验产品能否容纳至少几种实质不同的路径规则，同时让用户在进入或返回时理解当前内容允许什么。
- `DESIGN.md` 与机制 Demo 应在讨论后确定具体测试范围，清楚区分平台能力、内容规则与某次试用所用的参数。
