# 0005：产品 Demo 必须先有值得体验的内容

日期：2026-09-24｜状态：已确认的流程修正；product-01 v0.1 撤回为内部机制样本

## 本次项目会议的基线

此前的[决定 0003](0003-content-defined-trajectories.md)要求由内容决定可达路径，[决定 0004](0004-autonomous-demo-review.md)要求 Agent 自主产出并评审 Demo。product-01 v0.1 据此做出三段预写规则样本，功能测试通过，并在 `AUTO-REVIEW.md` 中被标成可交所有者试用。项目所有者实际打开页面后，指出这种评审没有评到产品与内容的本体。

## 新反馈与问题定位

项目所有者的原话包括：「你的demo不是一个类似小说的内容，而是过度的拟合了产品本身」「你的产品为什么要有hero页，这是官网？」「一个重要原则是保持简介〔按上下文理解为简洁〕」「你的故事产品没有商业价值，也没有意思」。他特别指出「三分钟前的选项已经不存在。现在的行动仍有很多，但它们属于这个被改变后的城市」这类句子像产品说明，不是有吸引力的故事。

这不是某一句文案或某个配色的问题。旧脚手架把“机制 Demo 可用中性测试内容”视为面向所有者试用的有效路径，真正内容创作却被放在机制试用以后；自动评审又把可点击、状态正确、屏幕适配作为主要通过依据。于是内容被编成展示三种规则的器材，界面加了介绍产品的 hero，作品反复解释自身机制。技术测试结果真实，但不能支持“合格产品 Demo”的结论。

## 已决定的改变

1. 保留“Agent 自主制作并评审”的工作方式，但评审对象必须是能被消费的产品体验，不是机制展厅。内容自定路径的原则继续有效；它不能替代内容本身的吸引力。
2. 每个 Demo 先有简短的产品价值命题和独立的内容创作简报，再写内容初稿并脱离界面审读。对叙事候选，应让人像读作品一样进入人物、事件或发现；这不把所有信息雨候选都规定为小说。
3. 面向所有者的 Demo 默认打开即进入代表性内容，只保留完成阅读、选择和辨认后果必需的界面。官网式 hero、产品口号、实验菜单和正文中的机制讲解不作为默认体验。必要说明必须由具体用户任务证明，而非为了“展示设计”。
4. 分开评审作品、产品体验和软件行为。功能测试通过只意味着路径按设计运行；不能宣布内容有趣或有商业价值。明显不合格的 Demo 标为内部样本并修订或撤回，不继续请所有者按合格产品试用。
5. product-01 v0.1 现仅保留为内部机制与反面案例，不再以“待所有者试用”或“已通过产品评审”表述。原始代码、测试和反馈保留，不删除历史。

## 影响、未知与下一段工作

有效的研究、内容决定路径原则和自动化工作方式保留；原 `MECHANISM.md` 的状态转移能力只作为内部能力证据。原 `AUTO-REVIEW.md` 的功能测试事实保留，其“可交付试用”结论被本次反馈推翻。实验脚手架、模板、Agent 规则和轮次状态同步修订。

下一段优先工作不是给 v0.1 换漂亮文案，而是重新回答 product-01 给人什么可持续的阅读价值，制作一份具体 `DEMO-BRIEF.md` 和可独立阅读的 `CONTENT-DRAFT.md`；通过内容审读后再决定下一版最少界面与路径规则。尚未决定该作品的题材、人物、商业模式或下一版是否沿用“窗边／停电／电台”。项目所有者对现有样本的否定不等于对整个信息雨愿景的否定。下一版是否有趣、是否值得继续，仍需实际体验检验。
