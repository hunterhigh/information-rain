# 0016：上下切换作品，左右选择剧情

日期：2026-10-09｜状态：已采纳，内容与界面迁移中

## 触发

`demo-v0.3.0` 的 61 部作品里，46 部少于 10 个非结局剧情节点；旧 23 部有 181 个三选节点、210 条向上剧情边。当前手机阅读态把上滑用于剧情、下滑用于下一作品，和所有者期望的纵向内容流不一致。38 篇新短篇的多数路径仅有两个剧情选择，完整体验偏短。

## 决定

- 在封面与阅读态，**上滑进入下一部作品，下滑返回上一部作品**；键盘上/下键沿相同语义。正文仍可纵向滚动，滚到边界后才由作品切换接管。
- 一篇故事内部只用左、右两个选择方向；每个非结局剧情节点最多两个出口。原有向上剧情边不能只在 UI 隐藏，必须逐条迁移并确认结局仍可达。
- 运行内容池中的每一部作品至少有 **10 个可达的非结局剧情节点**。这统计的是整部作品，不是每条路径都必须经过 10 次选择。节点数只是最低结构门槛；扩写还要增加新的现场、信息与后果，不能靠拆句、重复转场或无后果点击凑数。
- 原有 23 部作品与新增 38 篇一同进行文笔、视角、沉浸、选项兑现和路径因果审稿。编辑时保留每篇独立的声音与核心冲突。
- 在 61 部全部通过新图约束前，不把新手势界面部署到公开预览；封面传输优化可以独立发布。

## 验收

逐篇图检查验证节点数、出口方向、可达性、结局闭环和每条路径至少两次实质选择；逐篇编辑审读验证有价值的扩写、人物与物件连续性、文笔和结局兑现。网页行为测试验证封面与阅读态的上/下作品切换、左/右剧情选择、正文滚动边界及触摸取消。最后以手机真机走完整流程，记录发布版本和部署地址。

本决定更新[决定 0015](0015-full-screen-swipe-and-branch-navigation.md)的方向语义；其整屏跟手与过场目标仍保留。
