# 0012：单仓库内分产品源码与文档边界

日期：2026-09-30｜状态：项目所有者已确认

## 背景

长期方向包含工具 Agent 与分发产品。此前分发产品源码和工作记录仍放在 `experiments/round-01/`，根 `README.md` 同时承载技术愿景、产品状态和项目索引；商业策略与外部证据也混在一个研究目录。这使人难判断某段文字是愿景、产品要求、商业假设还是历史实验，也容易让未来两个产品共用错误的源码或部署边界。

## 决定

- 继续使用一个 Git 仓库，同时在 `products/<product>/` 为每个产品设独立源码边界。
- 当前分发产品源码位于 `products/distribution/reader-web/`，产品定义与路线图位于 `docs/products/distribution/`。
- 为工具 Agent 预留 `products/tool-agent/` 和 `docs/products/tool-agent/`。预留不等于已经批准该产品的实施范围、规格、技术栈或时间表。
- 技术愿景正文与愿景本体位于 `docs/vision/`；产品业务语言与实施路线按产品位于 `docs/products/`；商业策划位于 `docs/business/`；外部研究按主题位于 `docs/research/`；跨产品治理位于 `docs/project/`。
- `experiments/` 只保存有界实验、已撤回样本和可追溯的历史材料。正在持续演进的产品代码不放在实验编号目录。
- 每份文字只维护一个权威正文；入口和分类索引通过链接导航，不复制整段内容。
- 一个仓库不意味着两个产品共享构建、部署、数据模型或发布流程；只有在有具体共享需求后才另行决定。

## 工作影响

- 当前源码和研究资料保留 Git 历史并迁入各自目录；相关构建路径、相对链接、目录索引和工作基线一并更新。
- 根 `README.md` 用作简洁仓库说明；`START-HERE.md` 是当前工作入口，其他分类在各自 README 中导航。
- 新增文档前先判断它属于愿景、产品、商业、研究、治理还是实验；之后在相应索引登记状态、用途和权威位置。
- 工具 Agent 未来进入实施时，先独立建立产品本体、路线图和验收范围，不默认继承分发产品的业务术语和运行方式。

## 重审条件

当产品有独立团队或访问权限、不同合规边界、发布周期冲突，或单仓库导致构建和版本协作成本高于共享收益时，重新评估是否拆分 Git 仓库。没有这些证据前，不提前拆仓库或建共享代码层。
