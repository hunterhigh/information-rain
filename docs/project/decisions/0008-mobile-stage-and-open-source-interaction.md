# 0008：保留 9:16 移动端舞台并试用开源交互库

日期：2026-09-28｜状态：项目所有者已决定；本地 Demo 已实施，真机试玩未发生

## 决定

分发产品的核心内容舞台继续采用适配手机端和短视频内容的 9:16 竖屏画幅。桌面端把该舞台居中展示并保留两侧导航与信息栏，不能因为桌面空间充足而把内容画面扩成任意比例的全屏区域；手机端同样保持 9:16，并在可用高度不足时等比缩小，为底部导航和安全区留出空间。

本轮 HTML Demo 采纳 [Swiper](https://github.com/nolimits4web/swiper) v14.2.0 与 [XState](https://github.com/statelyai/xstate) v5.33.2：

- Swiper 只负责封面层的纵向跟手、速度判断、阻尼、回弹和作品索引切换；进入正文后暂停作品切换，避免阅读滚动误跳作品。
- XState 只负责封面、打字、可选择、节点过渡、结局及其他页面等语义状态；不复制 Swiper 的像素位移和手势物理。
- 删除原先固定 500ms 退出、600ms 进入以及 `wheelLocked` 的组合锁；当前封面切换时长为 280ms，并尊重减少动态效果的系统偏好。
- 两个依赖均以固定版本 CDN 接入，并保留无库时的基础降级逻辑；这适合当前单文件本地实验，但不是正式产品技术栈决定。

## 约束与后续判断

交互优化不得修改已保留 19 部作品的文字、分支、结局或封面。本轮内容审计仍为 19 部作品、386 个节点、184 个结局、578 条选择，内容 SHA-256 为 `98eff35162a3551505424b167e047a5a94e0900fea85aee6d84b864c8e99ac31`。

浏览器回归已覆盖桌面、390px 与 375px 宽度，确认 9:16、无横向溢出、进入阅读和方向选择可用。项目所有者仍需用手机真机判断连续滑动的触感与 280ms 参数；在此之前不能把浏览器模拟视为体验验收完成。

若试验成立，再决定将固定版本资产放入仓库或建立正式构建步骤，以降低 CDN 可用性和供应链风险。相关候选与采用边界记录在 [GitHub 开源项目参考](../../research/architecture/2026-09-28-github-project-references.md)。
