# 项目简报

> **范围更新（2026-09-29）**：本简报最初为项目知识库阶段编写。项目所有者之后采纳双产品方向，并确认当前实施目标是以分发 Demo 为基线，逐步形成可上线产品；工具产品不进入当前执行路线。现行范围以[决定 0011](decisions/0011-distribution-product-as-active-roadmap.md)和[分发产品实施路线图](../products/distribution/roadmap.md)为准。以下“第一阶段/明确不做”保留为历史起点，不能覆盖后续已批准范围。

## 问题

现有讨论分散在对话和实验中，缺少一个能区分已确认判断、候选假设、纠正记录与后续工作的长期项目入口。

## 使用者

- 项目所有者
- 后续共同研究、设计或实现这一产品愿景的协作者

## 第一阶段

- 建立本地 Git 仓库
- 用一份 README 汇总当前技术愿景、概念边界、合理性判断、纠正记录与关键未知
- 为后续研究、原型和实现保留可恢复的项目上下文

## 明确不做

- 产品代码
- 技术栈选型
- 外部服务或模型接入
- 部署、GitHub 远程仓库或公开发布
- 将尚未验证的愿景写成确定产品规格

上述为初始阶段边界。2026-09-23 项目所有者另行授权建立私有 GitHub 远端；见[决定 0002](decisions/0002-private-github-remote.md)。部署和公开发布仍不在范围内。

2026-09-24 项目所有者要求自动产出与评审本地机制 Demo；见[决定 0004](decisions/0004-autonomous-demo-review.md)。这允许仅用于实验的本地静态界面与规则代码，不意味着进入真实用户服务、付费模型接入或正式产品开发。首个 Demo 仍以手机尺寸为主要交互环境，不存储真实用户数据。

2026-09-28 项目所有者采纳了工具产品与分发产品并行的战略方向；「全梦」「信息雨」的术语边界及文字、插画、短视频渐进验证见[决定 0006](decisions/0006-two-products-and-medium-validation.md)。已有分发原型的本地 UI 维护获单独授权，不等于授权对外部署、修改既有作品内容或接入版权音乐。
