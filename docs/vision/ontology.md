# 技术愿景本体

状态：整理稿｜范围：长期技术愿景，不是当前产品规格

本文件规范项目在讨论长期技术愿景时使用的概念。它与具体产品的用户语言、功能和数据模型分开维护。产品文档可以引用愿景概念，但必须说明它在产品中的落点；不能因为愿景出现某个概念，就推定当前产品已经提供该能力。

## 核心概念

| 术语 | 愿景层含义 | 与当前分发产品的关系 |
| --- | --- | --- |
| **全梦** | 项目长期技术愿景的名称，描述面向生成式娱乐体验的广泛技术方向。 | 愿景名称，不是当前产品名称或功能承诺。 |
| **信息雨** | 在当前位置存在多个可到达后继的信息组织与移动方法。方向不必固定代表上下左右含义，候选之间也不必有预设的逻辑关系。 | 当前分发 Demo 在作品内部呈现多方向选择；具体产品称谓见分发产品本体。 |
| **推荐即生成** | 系统不只从现有内容池挑选内容，也可能决定下一刻为当前用户生成什么。 | 当前 Demo 使用预写作品，没有实时生成或个性化生成。 |
| **生成式世界/内容** | 可由生成系统持续构造或改变的情境、角色、事件和内容。 | 这是长期能力方向，不等于当前每一部作品都是动态世界。 |
| **媒介** | 承载体验的信息形式，例如文字、插画、声音或视频。 | 愿景允许多种媒介共存；当前 Demo 的内容与封面实现以文字和静态图像为主。 |
| **局部信息空间** | 围绕用户当前位置组织的一组可能后继及其可达关系。 | 当前 Demo 的节点和选择是预写、预连接的局部结构，不是实时计算的个性化推荐。 |

## 概念关系

```text
全梦（长期技术愿景）
├─ 信息雨（信息如何组织与移动）
├─ 生成式世界/内容（内容可能如何产生或变化）
├─ 推荐即生成（下一步内容如何由用户状态影响）
└─ 多媒介（体验如何表达）

分发产品是采用其中部分方法的一个独立产品；
工具产品是另一个独立产品方向。
```

## 使用规则

1. 愿景术语描述技术方向或可验证假设，不直接作为 UI 文案、数据字段或上线功能承诺。
2. 产品术语在 `docs/products/<product>/ontology.md` 定义。若产品用语与愿景同名，产品文档要说明两者映射和差别。
3. “长期希望具备”与“当前已经具备”必须分开表述。当前能力以产品基线和可运行实现为准。
4. 愿景改变时更新本体并留下决定依据；产品不需要因愿景文案改变而自动改名或重构。
