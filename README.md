# Information Rain

> 一个关于手机原生、推荐即生成、多维信息分发与生成式娱乐世界的长期思考和实验项目。

状态：愿景形成期
更新：2026-09-23

## 这个仓库是什么

这个仓库用于记录、澄清、批判和逐步验证一种潜在的新媒介与产品形态。

它当前不是一份已经确定的产品需求，也不是一个已经选定技术栈的软件工程项目。这里保存的是：

- 当前有效的技术愿景；
- 已经确认的概念边界；
- 讨论中出现并被纠正的误解；
- 尚未被证明的产品假设；
- 后续研究、原型和实现工作的恢复点。

## 一句话愿景

构造一种专注手机的生成式信息分发产品：推荐不再只从已有内容中挑选下一条，而是实时决定并生成下一刻的内容；用户也不再只能沿单轴瀑布流向下消费，而是在多个可到达的信息方向中移动、探索并形成自己的体验路径。

暂定名称是 **Information Rain / 信息雨**。

## 我们真正讨论的对象

这不是单独的 AI 小说、AI 短剧、互动小说或开放世界游戏。

我们讨论的是三种能力的交汇：

1. **信息雨**：替代单一信息瀑布的多方向信息分发与交互结构；
2. **生成式世界与内容**：由 AI 持续生成文字、声音、画面、角色、事件和环境；
3. **推荐即生成**：推荐系统不只是选择库存，而是决定下一刻应该为当前用户生成什么。

三者结合后，产品可能融合影视、短视频和游戏：

- 影视提供感官表达、人物、场景和情绪；
- 短视频提供低门槛、即时满足、手机原生和高吞吐分发；
- 游戏提供可探索空间、状态、行动和反馈。

融合不意味着产品必须在每一时刻同时像电影、抖音和游戏，也不意味着最终形态已经确定。

## 信息瀑布与信息雨

### 信息瀑布

传统信息流在任意时刻主要提供一个后继内容：

```text
当前内容
   ↓
下一条
   ↓
再下一条
```

用户可以接受或跳过，但平台一次主要给出一条前进路径。相邻内容不必存在逻辑关系。

### 信息雨

信息雨在当前内容位置提供多个可到达的下一信息：

```text
                 候选 B
                   ↑
候选 C  ←  当前内容  →  候选 D
                   ↓
                 候选 A
```

这里的上下左右只是示意。方向不必永久绑定时间、人物、因果、主题或视角，也不要求候选之间具有固定逻辑关系。

方向可以只是：

- 多个内容候选的入口；
- 用户表达选择的手势；
- 算法临时组织的局部信息空间；
- 下一轮实时生成的条件信号。

因此，信息雨的最小定义是：

> 用户在当前信息位置拥有多个可到达的后继，而不是只有平台排好的唯一下一条。

用户每移动一次，系统可以围绕新的位置重新生成下一片局部信息空间。

### 信息雨与媒介无关

信息雨描述的是信息如何被组织、到达和继续生成，不规定承载信息的媒介。

一个位置上的“信息单元”可以是：

- 一句话或一段文字；
- 图文卡片或照片集；
- 音频、对白或环境声；
- 短视频、Vlog 或短剧片段；
- 一个可以继续行动的互动状态；
- 上述媒介的任意组合。

因此，文字、图片和视频不是三个互斥产品，而是同一信息单元在不同延迟、成本、表达需求和设备条件下的渲染方式。产品可以先显示文字，再渐进补充图片，未来再替换或追加视频，而不改变信息雨本身。

### 回溯、回退与分叉

信息雨的多后继结构还带来一个信息瀑布通常不具备的潜在能力：用户可以沿已经走过的路径返回某个信息位置，并从那里尝试另一个后继。

这需要区分三种不同操作：

- **回看**：重新查看已经经历的内容，不改变当前世界状态；
- **撤销**：把当前有效状态恢复到此前位置，使后续经历不再属于当前时间线；
- **分叉**：保留旧经历，同时从此前位置建立一条新的可能路径。

传统信息流也可以打开浏览历史，但通常只能重新观看，不能改变后续内容的生成起点。信息雨如果保存位置、路径和世界状态，就可以把用户经历从一条不可逆序列变成一张可回退、可改选的个人体验图：

```text
A → B → C
    └→ D → E
```

用户体验到 C 后不满意，可以返回 B，再进入 D。这个动作不仅表达“我不喜欢 C”，还提供了更具体的反馈：在状态 B 下，用户看过 C 的结果后主动拒绝了这条变化，并愿意尝试另一种可能。

回退不是信息雨自动拥有的性质。系统必须保存节点身份、父子关系、用户路径，以及需要恢复的世界状态。旧分支究竟被删除、冻结还是继续作为可进入的可能性保留，目前仍是产品选择。

无限免费回退可能削弱某些体验中的后果感，但也可能强化探索、试错和反事实娱乐。项目不预设哪种价值更高；不同世界可以采用不同的可逆规则。

## 推荐即生成

传统推荐系统解决的是：

> 已有内容中，下一条展示哪一个？

推荐即生成解决的是：

> 根据用户此刻的位置、历史和可能兴趣，下一刻应该生成什么？

更严格地说，传统推荐器输出的是一个已有内容 ID；推荐即生成系统输出的是一份“下一内容规格”，包括题材、状态变化、表达媒介、长度、视角、节奏或其他生成条件，再由生成器渲染为实际内容。

“实时”不要求每一个像素都必须等到用户手势之后才从零计算。只要内容尚未在固定库存中完成、而是依据用户当前状态和位置动态决定，系统仍可使用相邻候选预生成、并行计算、缓存和渐进渲染来隐藏延迟。

暂定闭环如下：

```text
用户状态＋当前位置＋世界/IP约束
                ↓
系统生成多个可能的下一内容
                ↓
以信息雨的方式提供多个可达方向
                ↓
用户观看、滑动、点击、进入或行动
                ↓
行为成为下一轮推荐与生成的输入
```

用户路径不只是消费记录，也可能成为一种实时协作信号：用户通过移动告诉系统自己想看见哪类可能。

## 世界与 IP

这里的世界不等于固定剧情。

一个迷人的 IP 可以主要存在于：

- 可识别的规则；
- 空间和地理；
- 视觉、声音和语言风格；
- 阵营、角色与社会生态；
- 物品、能力和行动方式；
- 在这个世界中可能发生什么；
- 用户想进入并继续探索的欲望。

夜之城或洛圣都的吸引力并不完全依赖某个固定主角或唯一剧情。固定故事可以展示世界，但不是世界成立的必要条件。

因此，一个足够丰富的生成式世界可以成为内容母体，为差异很大的用户生成不同体验：战斗、关系、悬疑、生活、探索、财富、视觉奇观或纯粹的新鲜事件。

“一个世界观服务男频和女频”在这里不是严格的性别分类，而是一个例子：同一个世界底座可能支持差异巨大的娱乐偏好，而不必为每类用户重新制作一个内容宇宙。

### 世界的工作定义

在本项目中，世界暂定为一种持续的生成身份，而不是固定地图、固定游戏规则或固定剧情：

```text
世界
= 可识别的身份与气质
+ 内容生成的先验与边界
+ 已经形成的实体、关系和历史
+ 允许继续扩张的可能性
+ 用户或账号在其中留下的路径
```

世界可以同时承担传统平台中的媒体、栏目、IP、账号和入口功能。用户进入的不是某一部已经完成的作品，而是一个能够不断生产作品、事件和体验的位置。

世界是否仍是“同一个世界”，不取决于空间是否狭窄或题材是否一直不变，而取决于后续内容是否仍能从此前的身份、历史或生成谱系中成立。用户可以从末世第四天出发，最终进入太空与外星人决斗；如果这段扩张保留了足够的因果、身份或世界谱系，它仍可以属于同一个世界。

世界也可以具有极细颗粒度：人物的一秒、一个物品、一条新闻、一次战斗或一个遥远星系，都可以成为可进入的信息位置。

### 分发降低机会成本，但不消灭质量问题

个性化分发确实降低了传统内容的表达机会成本：一个小众内容不再需要挤占所有人的频道，只需被送到可能需要它的人面前。因此，同一世界可以容纳远比传统影视或游戏更多的题材和表达。

但这不等于系统完全不需要关心质量。它仍需避免生成失败、重复、错误匹配、过长等待和世界身份崩塌。这里的“质量”不应统一理解为文学深度，而应理解为当前信息对当前用户和当前位置是否有效。

## 两两交汇产生的邻近产品

三个要素中的任意两个结合，都可能形成有价值的产品方向。

### 信息雨 × AI 小说／文字世界

可能形成开放情节小说、沙盒文字游戏或多方向文字世界。

用户可以不断进入新事件、新人物或新世界，不要求体验收束为一条传统小说剧情。

### AI 世界／小说 × 推荐即生成

可以在统一的世界规则或 IP 中，为不同用户实时生成不同题材、节奏、人物入口和体验路径。

世界可以共享，剧情不必共享。

### 信息雨 × 推荐即生成

接近“AI 抖音”或生成式信息流：系统根据用户反应持续提供、生成或重组新的短内容。

当前公开产品已经接近其中一些部分，但通常仍是推荐已经生成的内容池，并未完整实现逐次曝光时为每个用户实时生成。

### 信息雨 × AI 短剧／视觉世界

可能形成开放视觉小说、可探索短剧或不断展开的视觉沙盒。

用户既可以像看短视频一样快速消费，也可以在感兴趣时进入人物、事件、场景或其他可能。

## 三者交汇的核心假设

如果生成式世界、推荐即生成和信息雨能够形成有效闭环，产品可能成为：

> 一个以手机为入口、拥有极高信息广度和生成能力、能够随用户移动实时改变、同时兼具观看与探索属性的个性化娱乐世界。

这里最值得验证的不是三个能力能否简单相加，而是它们结合后是否出现单独产品不具备的新体验：

- 用户能否感觉自己不是在翻页，而是在信息空间中移动；
- 多个下一方向是否比单一下一条带来真实的新自由度；
- 生成系统能否持续产生差异，而不是很快同质化；
- 世界能否无限扩张，同时仍然保持足够可识别的身份；
- 用户的路径能否反过来提高下一轮生成质量；
- 这种体验能否在手机的延迟、成本和交互限制内成立。

## 不应预设的价值标准

这个项目不以传统长篇叙事作为唯一评价标准。

生成娱乐可以因为以下价值成立：

- 快速刺激；
- 高频新奇感；
- 视觉奇观；
- 低承诺的即时娱乐；
- 巨大的题材广度；
- 不断进入新情境；
- 深度人物关系；
- 长期世界沉浸；
- 行动与后果；
- 社交和共同体验。

人物感情、固定剧情、长程记忆和故事收束都是可能的模式，但不是所有生成娱乐必须满足的条件。

短视频式的刺激、碎片化和高吞吐本身可以是有效价值，不能被先验视为低级、被动或失败。

## 当前需要保持诚实的地方

以下内容仍是愿景或假设，而不是已被证明的事实：

- 三种能力同时存在，就一定比两两结合的产品更好；
- 信息广度或密度越高，用户价值就必然越高；
- 大规模实时多模态生成在成本和延迟上已经适合消费级手机产品；
- 无限生成可以长期保持新鲜感和世界识别度；
- 个性化会自然形成数据壁垒；
- 这种产品会成为“最终娱乐模式”；
- 这种媒介可以在技术意义上被称为 AGI。
- 文字、图片和视频一定会按固定顺序替代彼此；更可能的情况是它们长期共存，并由系统按场景选择。
- 五年内实时视频、长程一致性和消费级成本一定全部解决；这是方向性预测，不能成为当前产品成立的前提。

“AIGC 世界的 AGI”目前更适合作为一种愿景比喻：它表达的是一个能持续生成广阔体验空间的通用娱乐系统，而不是已经满足通用人工智能的技术定义。

## 已经纠正的误解

以下判断已经被明确撤回，不应重新作为项目前提：

1. 信息雨的不同方向必须分别代表固定事务；
2. 相邻内容必须具有逻辑关系，信息雨才成立；
3. 所有生成娱乐都必须依赖深层人物感情和固定剧情；
4. 高频刺激和碎片消费意味着用户退化为被动接收者；
5. 世界型 IP 必须由所有用户共享同一条剧情；
6. “一个世界服务不同偏好”只能被理解为粗糙的人群分类。

## 邻近技术和产品线索

这些产品或研究分别验证了部分能力，但目前没有一个可以直接等同于本项目愿景：

- [AI Dungeon](https://aidungeon.com/)：开放式 AI 文字冒险与世界探索；
- [Meta Vibes](https://about.fb.com/news/2025/09/introducing-vibes-ai-videos/)：AI 生成视频的发现、创作与个性化信息流；
- [Showrunner](https://www.showrunner.xyz/)：模拟世界、持续角色和用户参与生成剧集；
- [Google DeepMind Genie](https://deepmind.google/models/genie/)：实时生成并探索可交互视觉环境。

它们分别接近开放生成、AI 信息流、可生成影视和实时世界模型，但完整的手机信息雨闭环仍是待验证方向。

## 与现实技术演进的联系

移动媒介的主流形式会受到网络、设备、生产工具和分发算法共同影响。4G 是移动视频增长的重要使能条件，但不是单一原因。CNNIC 在 2014 年已经判断，4G 覆盖、资费下降、大屏手机和移动端视频体验会共同推动用户从 Wi-Fi 场景转向移动视频；抖音则在 2016 年以短视频产品形态直接上线，而不是由抖音自身从图文产品转型。

- [CNNIC：第33次中国互联网络发展状况统计报告](https://www.cnnic.com.cn/IDR/ReportDownloads/201404/U020140417607531610855.pdf)
- [ByteDance milestones](https://www.bytedance.com/)

对信息雨而言，对应的基础条件不只是网络带宽，而是：

- 文本、图片和视频的生成延迟；
- 单个候选与整片局部信息空间的生成成本；
- 角色、物体和世界状态的一致性；
- 相邻候选的并行生成与预取能力；
- 手机上渐进呈现和不中断手势的能力。

当前图像生成已经支持低质量快速草稿、JPEG 等较低延迟输出和部分图片流式返回，这使“先文字、再渐进图片”的信息方块具备现实可行性。但官方资料仍提示复杂提示可能耗时达到两分钟，跨次生成中的角色与品牌一致性也可能失败。因此，一次出图很快不等于每次手势后都能稳定、低成本地即时出图。

- [OpenAI Docs：Image generation](https://developers.openai.com/api/docs/guides/image-generation)

当前更有用的媒介排序不是价值上的“文字大于图片大于视频”，而是实时生成的可行性阶梯：

```text
文字：最低延迟和成本，最容易维持语义与世界状态
图片：中等延迟和成本，显著提高情境与审美表达
视频：最高延迟、成本和连续性负担，但感官表达最强
```

产品应保持媒介无关，但第一版原型应沿这个阶梯逐层增加，而不是等待视频技术成熟以后才验证信息雨。

## 早期 Demo 假设（历史候选，未批准）

以下是较早讨论中的单个 Demo 假设。当前实验顺序以[产品实验脚手架](docs/project/experiment-scaffold.md)为准，这些细节不构成可直接制作的规格。该假设当时试图区分两种情况：

1. 多方向界面只是把普通信息流改成了四个下一条；
2. 推荐、生成和多方向移动结合后，确实产生了新的信息空间体验。

### 建议的体验形态

- 手机全屏只有一个当前信息方块；
- 屏幕边缘露出若干相邻候选的轻微预览，让多个可达方向可以被感知，但不显示机械菜单；
- 方向没有永久语义，每个相邻候选由当前内容、世界状态和用户路径共同决定；
- 用户滑向一个候选后，该候选成为新的中心，系统再围绕它生成下一片局部信息空间；
- 信息方块先返回短文字，随后渐进出现图片；图片尚未生成时不阻塞继续探索；
- 初始入口可以是“末世第四天”，但世界允许沿用户路径扩大到社会、文明、太空或其他尺度；
- 首屏周围候选可以预先生成，后续文字实时生成，相邻图片并行预取，用产品结构吸收当前模型延迟。

### 首版刻意不做

- 不做实时视频；
- 不做复杂账号和社交；
- 不要求多人共享同一剧情；
- 不规定上下左右的永久含义；
- 不预先建造完整世界地图；
- 不以长篇文学质量作为唯一成功标准。

### Demo 需要观察的证据

- 用户是否在十秒内意识到自己拥有多个可达方向；
- 用户是否感觉自己在移动，而不是反复打开分支菜单；
- 不同方向是否产生了足够不同、值得选择的内容；
- 文字先到、图片后到是否仍然形成完整体验；
- 世界大幅扩张后，用户是否仍认为自己留在同一个世界；
- 哪些路径信号足以改善下一轮候选，而不需要用户填写偏好表。
- 用户是否自然理解“回到过去查看”和“回到过去改选”是两种不同动作；
- 回退重选是否增加探索欲，还是让选择失去分量。

## 当前关键研究问题

### 信息雨本体

- 多个可达方向需要同时可见，还是可以通过手势逐步发现？
- 一个位置应该提供多少候选，才能产生自由度而不只是增加操作？
- 方向只是索引，还是会逐渐形成用户能够学习的局部规律？
- 信息雨与普通推荐列表、网格和分支菜单的决定性区别是什么？
- 回退后，旧经历应该被抹除、冻结，还是保留为一条可以再次进入的分支？
- 回看历史与撤销世界状态应该使用同一个操作，还是明确分开？

### 世界与内容

- 一个无限生成的世界，最少需要保持哪些不变量才仍然是同一个 IP？
- 世界可以只保持审美和规则，还是必须维护人物、历史或因果状态？
- 用户路径是否写入世界，还是只用于个人推荐？
- 多位用户是否共享世界事件，或者只共享生成规则？

### 推荐与生成

- 系统根据什么目标选择下一批候选？
- 如何兼顾熟悉、意外、广度和重复控制？
- 怎样区分用户真正偏好和一次偶然滑动？
- 数据壁垒来自用户偏好、世界状态、生成策略，还是三者之间的轨迹？

### 手机体验

- 什么是第一次打开后十秒内就能理解的最小交互？
- 怎样保留短视频的低摩擦，又不把信息雨重新退化为单轴瀑布？
- 文字、图片、音频和视频应该怎样根据延迟与成本逐层渲染？
- 用户何时只观看，何时探索，何时真正改变世界？

## 当前项目边界

现在做：

- 继续澄清技术愿景；
- 保存判断、纠正和决定；
- 研究邻近产品与技术；
- 设计能够区分关键假设的原型；
- 在获得证据后逐步形成产品定义。

现在不做：

- 提前宣布最终产品形态；
- 因为已有一个文字 Demo 就把产品定义为互动小说；
- 提前锁定移动端技术栈；
- 接入真实用户、付费模型或生产数据；
- 把一次成功生成当成稳定系统能力；
- 以传统影视、小说或游戏的标准单独裁判这个新媒介。

## 当前恢复点

当前按[产品实验脚手架](docs/project/experiment-scaffold.md)先外部研究、第一性原理推演，再逐个讨论候选产品。每个产品需要整理后的完整设计、可操作的机制 Demo，以及随后制作的三种内容体验。旧的单轴 R01-B 方案已排除；[第一轮登记](experiments/round-01/PLAN.md)目前只记录候选状态，不是 Demo 规格。

原型必须真正区分以下两种情况：

1. 它只是把普通信息流换成了更多方向；
2. 它确实让用户感到自己进入了一个可移动、可生成的信息空间。

原有二维文字世界 Demo 是探索材料，不是当前产品定义，也不是必须继承的实现基础。

## 工作约定

- 新想法先标明是事实、假设、设计选择还是愿景；
- 用户纠正概念时更新当前基线，不为维护旧论证而抵抗；
- 重要产品决定写入 `docs/project/decisions/`；
- 产品设计应说明外部信息、推演过程和 Agent 自己的取舍；
- 尚未获得证据的内容不写成确定事实；
- 当项目进入可运行原型阶段时，重新评估技术栈、成本、数据与风险。
